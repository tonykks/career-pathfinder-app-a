00

Git과 GitHub는 왜 필요한가?

VERSION CONTROL BEFORE PUBLICATION

Web App이 완성되었다고 바로 Internet에 공개하지 않습니다. 먼저 현재 완성본을 Version으로 기록하고, 공개해도 되는 파일만 골라 GitHub에 올립니다.

GIT

내 컴퓨터의 Version 기록

파일이 어떻게 바뀌었는지 기록하고, 특정 시점의 완성본을 Commit으로 남깁니다.

GITHUB

Internet의 Remote Repository

Local Git의 기록을 GitHub에 Push하여 보관·공유·검토할 수 있게 합니다.

Commit = 내 PC에 기록
Push = GitHub로 전송
Deploy = 실제 Web으로 공개

01

Push 전에 반드시 공개 범위를 먼저 점검한다

PUBLICATION PREFLIGHT

이번 App A에서는 지니가 먼저 공개 예정 파일, 제외 파일, Secret, Repository Root, README 상태를 보고했고 사람이 확인한 뒤 Push를 승인했습니다.

1
공개 파일 목록

App 실행에 필요한 최종 파일만 올릴지 확인합니다.

2
내부 Agent 기록 제외

BRIEF, STATE, Research 원본, QA 기록, Prompt 등 내부 협업 자료는 공개하지 않습니다.

3
Secret Scan

API Key, Token, Password, .env, 개인정보, Local 절대경로가 없는지 검사합니다.

4
Repository Root

상위 작업실 전체가 아니라 app-a-gemini만 하나의 독립 Repository가 되게 합니다.

5
사람 승인

지니가 READY라고 해도 Push는 학생이 명시적으로 승인한 뒤 진행합니다.

02

공개 App과 내부 작업실을 분리한다

PUBLIC FILES VS INTERNAL RECORDS

GitHub 공개Local 내부 보관
index.htmlagent-collab-kit/
style.cssPROJECT_INTENT.md / BRIEF.md
app.jsSTATE.md / DECISIONS.md / VERIFICATION.md
data.jsResearch 원본 / Reviewer 보고서
README.md / LICENSE / .gitignoreAgent Prompt / Test Script / 내부 기록
핵심: GitHub는 작업실 전체를 복사하는 곳이 아니라, 공개하기로 결정한 완성품과 필요한 설명만 올리는 곳입니다.
03

Local Git — 현재 완성본에 Version 이름표를 붙인다

INIT → ADD → COMMIT

git init git branch -M main git status git add . git status git commit -m "feat: Initial release of Career Pathfinder App A"

git status를 Commit 전후에 반복해서 보는 이유는 “내가 의도하지 않은 파일까지 함께 기록되는가?”를 사람이 확인하기 위해서입니다.

05

사람이 승인하면 처음으로 Push한다

HUMAN APPROVAL → PUSH

git remote -v git push -u origin main

“Push 버튼은 AI가 아니라 사람이 허락한다.”

이번 App A는 실제로 tonykks/career-pathfinder-app-a Repository에 Push되었고, 내부 Agent 문서는 공개되지 않은 상태로 검증했습니다.

06

Push 후에는 GitHub 화면을 다시 검증한다

POST-PUSH VERIFICATION

  • main Branch에 의도한 공개 파일만 있는가?
  • Agent Prompt·Research·QA 내부파일은 없는가?
  • Secret / 개인정보는 없는가?
  • README와 LICENSE가 정상 연결되는가?
  • Local main과 origin/main이 일치하는가?
  • working tree clean인가?
App A 실제 결과: 공개용 정리 후 Root에는 .gitignore / LICENSE / README.md / index.html / style.css / app.js / data.js만 남겼습니다.
07

무엇을 공개할지 결정

Public/Private, 공개 파일, Push 승인처럼 되돌리기 어렵거나 외부에 영향을 주는 결정은 사람이 맡습니다.
