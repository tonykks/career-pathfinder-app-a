02

왜 Coding 전에 Research와 Cross-check를 할까?

RESEARCH BEFORE CODING

문제

기능은 만들 수 있어도 내용이 틀릴 수 있다

“수학을 좋아하면 공학 직업을 몇 점 더 준다” 같은 규칙은 Programming으로 쉽게 만들 수 있습니다. 하지만 그 규칙이 진로 교육에서 타당한지는 별도의 문제입니다.

해결

먼저 자료를 찾아 근거를 확인한다

공식 진로자료를 먼저 조사하고, 확인되지 않는 부분은 AI가 사실처럼 꾸미지 못하게 합니다. 그 다음에 Coding을 시작합니다.

바로 Coding하면Research 후 Coding하면
AI가 빈칸을 그럴듯하게 채울 수 있음공식 근거가 있는지 먼저 확인
잘 작동하지만 믿기 어려운 App이 될 수 있음근거와 가정을 구분한 App이 됨
오류 발견이 늦어짐Coding 전에 방향 오류를 줄임
03

그럼 학생은 무엇을 해야 할까?

HUMAN ROLE IN VIBE CODING

학생은 Programmer가 아니라
“내가 원하는 방향을 결정하고, AI의 결과를 승인하는 사람”입니다.

학생이 하지 않아도 되는 일
  • HTML/CSS/JavaScript를 직접 전부 작성하기
  • 모든 공식 사이트를 혼자 검색하기
  • 모든 Bug를 직접 고치기
  • 여러 AI의 작업 결과를 수동으로 합치기
학생이 반드시 해야 하는 일
  • 내가 무엇을 만들고 싶은지 말하기
  • AI가 이해한 내용이 맞는지 확인하기
  • 중요한 변경을 승인하거나 거절하기
  • 마지막 결과를 직접 써보고 판단하기
04

왜 학생이 토비와 지니를 연결해야 할까?

WHY THE HUMAN BRIDGE MATTERS

토비와 지니는 서로 맡은 일이 다릅니다. 토비는 학생과 대화하며 “무엇을 왜 만들고 싶은가”를 지키고, 지니는 실제 개발환경에서 “어떻게 만들고 검증할 것인가”를 관리합니다. 현재 구조에서는 두 AI가 학생의 의도를 완전히 자동으로 공유하는 것이 아니므로, 학생이 둘 사이의 중요한 정보를 연결해 줍니다.

학생“내가 원하는 것은 이것이야.”
→
토비의도 정리 · BRIEF 검토 · 방향 확인
→
학생승인·수정 내용을 지니에게 전달
→
지니Agent 배정 · Research · Coding · Test
학생은 단순한 “복사·붙여넣기 담당”이 아닙니다.
실제 역할은 의도를 보존하는 최종 책임자입니다. 무엇을 전달할지, 무엇을 승인할지, 무엇을 다시 물어볼지를 결정하는 사람이기 때문입니다.
05

예시로 보면 왜 연결이 필요한지 더 쉽게 알 수 있다

A SIMPLE CLASSROOM EXAMPLE

학생 → 토비
지니가 만든 BRIEF를 봤는데, 바로 Coding하려고 해요. 이대로 승인해도 될까요?
토비
아직 Research 단계가 빠져 있어요. 진로 추천에 쓸 자료를 먼저 조사하고 다른 AI가 Cross-check한 뒤 Coding하도록 수정하는 것이 좋습니다.
학생 → 지니
BRIEF를 수정해 주세요. Coding 전에 공식 진로자료 Research와 독립 Cross-check 단계를 넣어 주세요. Research가 통합된 뒤에만 Coding을 시작하세요.
지니
수정했습니다. Geni-Research가 Research하고, 애니가 독립 검토한 뒤 제가 통합하겠습니다. 그 전에는 Coding하지 않겠습니다.
이 장면에서 학생은 Code를 한 줄도 쓰지 않았지만 Project의 품질을 크게 바꿨습니다. 만약 학생이 토비의 검토 없이 바로 “승인”했다면, 근거가 부족한 추천 규칙으로 App이 만들어질 수도 있었습니다.
06

왜 중간중간 사람의 승인이 필요할까?

HUMAN-IN-THE-LOOP

AI가 잘하는 것사람이 맡아야 하는 것
빠르게 조사하고 정리하기그 방향이 내가 원하는 것인지 판단하기
기능을 만들고 Test하기그 기능이 정말 필요한지 판단하기
여러 대안을 제안하기어느 대안을 선택할지 결정하기
오류를 찾아 수정하기완성 결과가 처음 목적과 맞는지 확인하기
Human-in-the-loop(사람이 중요한 지점에서 확인하는 구조)란 AI가 모든 것을 끝까지 마음대로 결정하게 두는 것이 아니라, 목적이나 방향이 바뀔 수 있는 중요한 지점에서 사람이 확인하고 다시 진행시키는 방식입니다.

학생 실행“내가 원했던 것과 같은가?”
  • App이 실행되는가?
  • 버튼과 계산이 정상 작동하는가?
  • Research에서 확인한 내용이 올바르게 반영되었는가?
  • 처음 내가 만들고 싶었던 App과 같은가?
  • 다르다면 무엇을 바꾸고 싶은가?

“Vibe Coding에서 사람의 가장 중요한 일은 Code를 직접 쓰는 것이 아니라,
AI가 올바른 방향으로 일하도록 연결하고 마지막에 목적과 결과가 같은지 판단하는 것이다.”

다음 수업에서는 실제로 지니가 만든 App A를 실행해 보고, “잘 작동하는가?”와 “처음 의도와 맞는가?”를 따로 평가한 뒤, 필요하면 App B의 requirements.md를 다시 설계하여 두 결과를 비교할 수 있습니다.
