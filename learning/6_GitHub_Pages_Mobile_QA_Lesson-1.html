00

GitHub에 올린 Source와 Google AI Studio의 공개 App은 다르다

REPOSITORY ≠ WEBSITE

GITHUB REPOSITORY

검증된 Source Code를 보관

GitHub는 최종 기준 Source를 보관하는 곳입니다. Google AI Studio에서는 이 Repository를 Import해 Preview한 뒤 Publish합니다.

GOOGLE AI STUDIO

Import → Preview → Publish

GitHub의 검증된 main을 Google AI Studio로 Import하고 Preview를 확인한 뒤 *.ai.studio 공개 URL로 Publish합니다.

02

localhost가 아니라 실제 배포 URL에서 다시 Test한다

AI STUDIO PUBLIC URL ACCEPTANCE

  • 첫 화면이 정상 로드되는가?
  • 별점 입력과 Custom Subject가 작동하는가?
  • Top 2 결과가 계산되는가?
  • 커리어넷 등 외부 링크가 열리는가?
  • PNG/PDF 다운로드가 실제 배포주소에서도 작동하는가?
  • Console에 치명적 Error가 없는가?
핵심: Localhost PASS와 Internet 배포 PASS는 별개입니다. 실제 사용자가 접속할 주소에서 다시 확인해야 합니다.
03

실제 스마트폰에서 보니 Web 화면은 다시 손볼 필요가 있었다

REAL DEVICE RESPONSIVE TEST

Desktop에서는 괜찮아 보였지만 스마트폰에서는 직업명과 배지가 공간을 서로 차지하고, 긴 직업명이 어색하게 줄바꿈되며, 출처와 링크가 좁은 공간에서 경쟁하는 문제가 보였습니다.

발견한 문제수정 방향
직업명 + 참고 배지 가로 충돌모바일에서는 세로 흐름으로 분리
긴 제목의 한 글자 고립 줄바꿈keep-all + 충분한 Text 폭
Card 내부 실제 본문 폭이 좁음모바일 Padding 미세 조정
출처 + 상세 링크 공간 경쟁각각 별도 줄로 배치
하단 버튼100% 폭 세로 배치
04

중요 — Web 화면과 PNG/PDF 출력물은 서로 다른 UI다

SCREEN UI VS EXPORT TEMPLATE

WEB UI

스마트폰에 맞춰 Responsive

화면 폭에 따라 Card, Button, Text가 자연스럽게 재배치되어야 합니다.

PNG / PDF REPORT

고정된 인쇄형 Layout

다운로드 결과물은 이미 보기 좋았으므로 모바일 Web 수정 때문에 Report CSS가 바뀌지 않도록 보호했습니다.

Regression 원칙: Web UI를 고쳤는데 PNG/PDF가 망가지면 수정은 실패입니다. 따라서 기능 하나를 고쳐도 기존 정상 기능을 다시 Test해야 합니다.

06

Code는 고쳤는데 스마트폰에서 예전 화면이 보일 수도 있다

CACHE AWARENESS

Google AI Studio에서 Republish가 끝났어도 Browser Cache 때문에 실제 스마트폰에서 이전 화면이 보일 수 있습니다.

판별: GitHub main과 AI Studio Preview가 최신인데 실제 스마트폰 표시가 다르면 먼저 새로고침·Cache를 확인하고, 필요하면 AI Studio에서 Republish한 뒤 공개 URL을 다시 확인합니다.
